# Rednetline Cascade

Скрипт каскадной переадресации трафика на VPS. Работает через ядро —
DNAT и MASQUERADE в iptables, без прокси-демонов и лишних процессов.

```
клиент  ──►  [ этот VPS: DNAT ]  ──►  зарубежный сервер
```

## Зачем это нужно

Клиент подключается к ближайшему или «чистому» VPS, а трафик уходит на другой
сервер — тот, что обеспечивает выход в нужную страну. Для клиента всё выглядит
так, будто он говорит напрямую с этим VPS: зарубежный адрес в конфигурации
клиента не фигурирует вообще.

Подходит для WireGuard и AmneziaWG (UDP), VLESS/XRay и MTProto (TCP), а также
для любых других TCP/UDP-сервисов, включая проброс с изменением порта (SSH,
RDP, нестандартные порты).

## Возможности

- **TCP и UDP**, разные порты входа и выхода.
- **Скорость ограничена только каналом**: трансляция в ядре, никаких
  пользовательских процессов в пути трафика.
- **Работает поверх ufw и без него.** При активном ufw правила записываются в
  `before.rules` и подхватываются самим ufw; при его отсутствии — прямо в
  iptables с сохранением через `netfilter-persistent`.
- **Переживает перезагрузку.** Проверено на живом сервере: до и после reboot
  совпадают все правила, цепочки, переходы и `ip_forward`.
- **Учёт трафика по каждому туннелю**, в обе стороны, в реальном времени.
- **Проверка результата**: после применения скрипт читает живые правила ядра и
  сообщает, если чего-то не хватает.
- **Защита от потери доступа**: проброс SSH-порта сервера требует явного
  подтверждения.
- Разумные проверки ввода: порт `0`, порт `0443` (iptables читает ведущий ноль
  как восьмеричное и превратил бы его в 291), мусор вместо IP, петля на
  собственный адрес.

## Требования

- Linux с iptables (проверено на Ubuntu 24.04, ядро 6.8, iptables 1.8.10)
- права root
- ufw — опционально; при его наличии используется автоматически

## Установка

```bash
wget -O rednetline-cascade.sh \
  https://raw.githubusercontent.com/v1psme/Kaskad/master/rednetline-cascade.sh
chmod +x rednetline-cascade.sh
./rednetline-cascade.sh install
```

Скрипт скопирует себя в `/usr/local/bin/rednetline`, после чего доступен как
команда `rednetline` из любого каталога.

## Использование

```bash
rednetline add udp 51820 203.0.113.10          # UDP, порты входа и выхода совпадают
rednetline add tcp 443 203.0.113.10 8443       # TCP, 443 на входе → 8443 на выходе
rednetline add tcp 2222 203.0.113.10 22 --force  # проброс SSH (нужен --force)
rednetline list                                # правила и трафик по ним
rednetline status                              # диагностика
rednetline delete udp 51820                    # удалить правило
rednetline flush                               # удалить все правила проекта
```

Без аргументов запускается интерактивное меню.

| Команда | Что делает |
|---|---|
| `add <tcp\|udp> <вход.порт> <IP> [вых.порт]` | добавить или заменить правило |
| `delete <tcp\|udp> <вход.порт>` | удалить правило |
| `list` | правила и трафик по каждому туннелю |
| `status` | диагностика: бэкенд, форвардинг, ufw, состояние цепочек |
| `apply` | применить конфиг к ядру |
| `flush` | удалить все правила проекта |
| `install` / `uninstall` | установить себя в систему / удалить полностью |
| `menu` | интерактивное меню (по умолчанию) |

Флаги: `--force` (разрешить проброс SSH-порта), `--direct` (писать прямо в
iptables даже при активном ufw), `--install-deps` (без вопросов поставить
`iptables-persistent`), `--no-bbr` (не включать BBR).

## Настройка клиента

1. Добавьте правило на этом VPS: протокол, входящий порт, адрес и порт
   назначения.
2. В клиенте замените адрес зарубежного сервера на **адрес этого VPS**.
   Порт — только если входящий и выходной порты различаются.

## Как это работает

### Единственный источник правды

Все правила хранятся в `/etc/rednetline-cascade/rules.conf`. При любом
изменении ядро пересобирается из этого файла целиком, а не правится точечно.
Отсюда идемпотентность: повторный `apply` даёт ровно то же состояние, а
дубликатов и «мёртвых» правил не возникает в принципе.

### Свои цепочки

Всё, что создаёт скрипт, живёт в отдельных цепочках и не смешивается с чужими
правилами:

| Цепочка | Таблица | Назначение |
|---|---|---|
| `RLN_PRE` | nat PREROUTING | DNAT — подмена адреса назначения |
| `RLN_POST` | nat POSTROUTING | MASQUERADE — подмена источника |
| `RLN_FWD` | filter FORWARD | разрешение проброса |
| `RLN_STAT` | mangle FORWARD | счётчики трафика |

Чужие правила (ufw, Docker, fail2ban) не затрагиваются: скрипт добавляет
переходы в свои цепочки, а не переписывает системные.

### Два бэкенда

**При активном ufw** правила записываются тремя блоками в `/etc/ufw/before.rules`
и загружаются самим ufw при старте. Перед записью нового файла он проверяется
через `iptables-restore --test`, и только потом заменяется; прежняя версия
сохраняется в `before.rules.rln.bak`. Такой путь не создаёт второго загрузчика
правил, а значит исключает конфликт «кто кого перезапишет» при загрузке.

**Без ufw** правила применяются напрямую в iptables и сохраняются через
`netfilter-persistent`. Если его нет, скрипт предложит установить
`iptables-persistent` (в неинтерактивном режиме — только с `--install-deps`).

### Учёт трафика

Счётчики живут в цепочке `RLN_STAT` таблицы `mangle`. Эта цепочка проходится
**каждым** пакетом, поэтому цифры точные — в отличие от счётчиков правил DNAT,
которые считают только первые пакеты соединений (так работает таблица nat).

## Надёжность

- Проверка входных данных до применения: порт, IP, петля на собственный адрес,
  занятость порта локальным сервисом.
- Отдельная защита от потери доступа: если входящий порт совпадает с портом
  SSH этого сервера, операция отклоняется, пока не указан `--force`.
- Проверка после применения: скрипт читает живые правила ядра и сообщает о
  расхождении.
- Бэкапы изменяемых системных файлов (`before.rules`, `/etc/default/ufw`).
- `flush` и `uninstall` удаляют **только своё** — правила других сервисов
  остаются на месте.
